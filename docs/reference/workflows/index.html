Workflows

A Workflow is a Python script written to be run repeatedly through the Workflow Manager, rather than loaded once from a saved session.

Workflows

Overview

A Workflow is a Python script written to be run repeatedly through the Workflow Manager, rather than loaded once from a saved session.

Workflows can automate tasks such as ranking wells, building a set of plots, or exporting a report, and can be shared between users.

Accessing the Workflow Manager

Workflows are managed and run from the Workflow Manager, opened from the Workflows group of theHome Ribbon Tab.

Types of Workflow

There are two kinds of workflow script, distinguished only by their file extension:

Simple Workflows (.s3py)

A .s3py workflow takes no arguments. Clicking Run executes the script directly.

Parameterised Workflows (.py)

A .py workflow declares arguments using Python's argparse, so a single script can be re-run against different data. When such a workflow is selected, S3analyse reads its arguments and shows them as Required and Optional fields above the list (see Arguments below).

Workflow Manager

The Workflow Manager lists every available workflow, grouped under category headings, sorted alphabetically within each category.

The list details the filename of the workflow and a description of its operation, lifted from the workflow file.

A user can select a workflow from the list be clicking on the appropriate row of the list. Selecting a workflow shows its details in the panel below the list:

The workflow panel details the:

  • Name and description of the selected workflow.
  • View Script opens the underlying script file in the preferred available editor.
  • Any Arguments or Options are listed for the user to fill out. Appropriate options may be types in or selected from a dialog opened via the corresponding Set Arguments button.
  • Run will runs the workflow. For a Parameterised Workflow this stays disabled until every Required argument has a value (see Arguments below).

While a workflow is running, a progress bar and Cancel button are shown in place of the list. Close dismisses the Workflow Manager.

Adding and Organising Workflows

Workflows do not need to be individually registered or imported. Any .py or .s3py script placed in a Workflows folder is picked up automatically, and the Workflow Manager updates immediately as scripts are added, edited or removed.

Workflow scripts are read from a Workflows folder in either of these locations:

  • Workflows to be shared by every user of the machine:
    • %ProgramData%\Sciencesoft Ltd\S3analyse\Workflows
  • Workflows available only to the current (roaming) user.
    • %AppData%\Sciencesoft Ltd\S3analyse\Workflows

The folder a script is placed in becomes its category in the Workflow Manager list. Scripts placed directly in the Workflows folder (not in a subfolder) are grouped under General. A subfolder name can be prefixed with a number and a space (e.g. 02 Well Surveillance) to control the order categories are listed in; the number itself is not shown.

A "Modules" subfolder is not scanned for workflows, use it to hold shared code that your scripts import.

Arguments

For a Parameterised Workflow, each argument the script declares is shown as a text field, split into Required and Optional sections. Optional fields can be left blank to use the script's own default value.

If an argument's name refers to a Case, Well, Grid Property or Summary Vector, S3analyse recognises it and adds a Set Arguments button next to the field to pick values from the current project instead of typing them.

If a project has only one Case loaded, its Case field is filled in automatically.

Entering more than one comma-separated value into an argument runs the workflow once for every combination of the values entered across all such arguments, e.g. two Cases and three Wells run the workflow six times.

Running a Workflow and Viewing Output

Click Run to execute the selected workflow (or once per combination of argument values, see above). A busy cursor is shown while it runs; Cancel stops it early.

Anything the script prints is written to the S3analyse log file only. A workflow can instead show results directly to the user in a dedicated Output window, intended for output that should actually be read or copied.

If the script itself fails, a Python Script Error message is shown with the details.
