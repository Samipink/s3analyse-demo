Text Files

Data is often collected in Text Files and these can come in various formats. S3analyse supports many text formats through a flexible approach to parsing the text data.

In general the recommended text format comprises of a Header section of keywords specifying the data origin name, start date, date format, etc. followed by tables of data with column headers containing property names, units, well names, etc. These can be split over multiple Pages.

Examples of various supported text file formats can be found in Text File Examples.

Adding Data from Text Files

Data can be added in two ways:

  1. Text files can be loaded directly.
  2. Text files can be added to a loaded data set as Observed Data.

Loading a text file directly creates a new dataset in the Project View; adding it as Observed Data attaches its vectors to an existing loaded project for comparison against simulated results.

Text File Format

Text files are comprised of a Header Section and a Data Section:

The Header Section contains information about the data as a whole, such as case name, start date, etc.

The Data Section contains a table of property columns; a column header, units, well name, etc. and a the property values.

Comment Lines

Comment lines can be added to the file. These are defined with a double dash "--" at the start of the line. Any text following these is disregarded. These are useful to add context notes and simulation references to the start of a text file.

Formatting Columns

Data should be formatted in a way to determine the individual columns of data and their associated column headers. The reader assumes a single column delimiter type on each line. It will automatically detect the delimiter in the following order of priority:

  1. Tabs ("\t")
  2. Commas (",")
  3. Spaces (multiple spaces are treated as a single delimiter)

Note: Tables should be consistently formatted throughout and not mix delimiters. Any variation in formatting may lead to the data failing to load or being misinterpreted.
