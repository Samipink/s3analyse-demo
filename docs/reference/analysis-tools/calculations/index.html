Calculations

The Calculations functionality allows new vector properties to be generated from existing (loaded or previously calculated) data via a formula.

Calculations

Overview

The Calculations functionality allows new vector properties to be generated from existing (loaded or previously calculated) data via a formula.

New vector properties are created by defining a formula containing variables, associating the variables with existing vectors, setting the name and location in the Project View node for the created property, and specifying whether to apply the calculation to all cases in an ensemble, or to all items (Wells or Solution timesteps, for example, depending on the type of data) in the data set.

Note that, although the vector properties are generated when the calculation is initially carried out, they are only evaluated when the vector is used (on a Line Plot or Grid Display, for example).

Accessing the Calculations

The Calculations dialog can be accessed in two ways:

  1. Clicking on Calculations in the View Actions group of the Home Ribbon Tab.
  2. Double-clicking on the Designs node under the Calculations node within the Calculated Data node in the Project View.

Calculations Dialog

The Calculations dialog has two areas: the left panel displays and manages the collection of calculations created during the current session; the right panel is the editor and is populated with the currently selected calculation.

List of Calculations

The left panel shows all calculations that have been created in the current session. Each item has three elements:

  1. An icon: The icon can be one of:
    1. Line Plot: Indicating that the calculation creates a new summary data vector from existing summary vectors.
    2. Grid Display: Indicating that the calculation creates a new grid property vector (INIT or solution data) from existing grid property vectors.
    3. Calculator: Indicating that the type of vector to be created by the calculation has not yet been specified.
  1. An identifying name for the calculation that includes the name of the resulting calculated vector and the formula used to create it. (Note that it is possible for two different calculations to have the same result vector name and calculation formula and therefore the same identifier.)
  1. The Delete, which allows any of the calculations to be removed from the list.

New calculations can be added by clicking Add New which creates a new, blank calculation item with the default name NEW.

When the Calculations dialog is first displayed it contains no calculations, so the Add New button must be clicked to add one.

Calculation Editor

The right panel on the Calculations dialog comprises the controls for designing and executing new calculations.

Result Vector Properties and Formula

The properties of the created vector and the formula to be used to calculate it are set in the top panel:

  1. Result Name: The short name of the vector property to be created (this is what will appear in the Project View).
  1. Formula: This is the expression that will be used to define the calculation to be performed. The formula will generally contain variables that can be associated with existing data values. Many functions can be used in the formula, including all the usual analytic functions (SIN, COS, EXP, LOG, etc.), and several other useful function (such as a lookup function, a random number generator, and special CUMMIN and CUMMAX functions for solution data. In addition, there are sum and average functions, which can be used to sum values over multiple items (over wells, for example). The complete set of supported functions is set out below.
  1. Units: The units of the created vector can be selected from the dropdown, which contains all supported units. These units will be shown in the axis titles when the created vector is displayed on a line plot.
  1. Description: The longer description of the created vector can be set. This will be shown in the axis titles when the created vector is displayed on a line plot.

Variables

When the formula is set, the formula expression is parsed and free of errors any variables it contains are identified (variables can be any sequence of alphabetic characters or digits, or underscores; the variable cannot begin with a digit). The list of variables is then displayed in the yellow Variables table section of the Calculations dialog. The yellow colour indicates that the rows of the table are drag and drop targets (that is, the properties to be associated with the variable must be dragged from the Project View and dropped onto the corresponding variable row of the table).

In the example below there are two free variables, a and b, in the formula y = a + b. These have been associated with the vectors WOPR and WWPR from well B1.

The Variables Table

The variables table has several columns containing information about the associated vector and / Padlock buttons that can be used to specify whether the vector or its properties are fixed when applying the calculation to multiple cases or items (see below). The number of columns that appear depends on the associated vectors. The full list of possible columns is:

  1. / Fix lock button [always present]: If this is locked, the associated vector’s case or item, etc., will not change when the calculation is applied to different cases or items. The exact vector that is associated with the variable will always be used in every evaluation of the calculation.
  1. Variable [always present]: the name of the variable in the formula.
  1. Associated Vector [always present]: The path in the Project View to the vector that is associated with the variable. (This is blank if no vector has been associated with the variable.)
  1. Case [always present]: The name of the case from which the associated vector comes. When the current project contains multiple cases, this is a dropdown that displays all the available cases and allows the case of the associated vector to be changed from the case of the vector that was dropped. Usually, this will not be necessary, but it can be used to set up a calculation that involves the difference of a vector between two different cases. Note, though, that care must be taken to ensure that the two cases have the same number of timesteps (for summary data) or grid cells (for solution data), otherwise the calculation cannot be performed.
  1. / Fix Case Lock button [present only if the current project contains multiple cases]: If this is locked, the associated vector’s case will not change when the calculation is applied to different cases. Other properties (item names, etc.) will change when the calculation is applied to different items (if they are not also fixed).
  1. Item (Well, Timestep, etc.) [present only if the associated vector has a property that can be ‘looped over’]: The column displays the item name of the associated vector (well name, timestep, etc.). This is a property of the associated vector that can be changed in each evaluation of the calculation to apply the calculation to all of the corresponding items (wells, timesteps, etc.) in the case.
  1. / Fix Item Lock button [present only if the associated vector has a property that can be ‘looped over’]: If this is locked, the associated vector’s item will not change when the calculation is applied to other items.
  1. Item2 (possibly completion index, for example) [present only if the associated vector has a second property that can be ‘looped over’]: The column displays the name of the second property of the associated vector. This is a property of the associated vector that can be changed in each evaluation of the calculation to apply the calculation to all of the corresponding secondary items (completions, for example) in the case.
  1. / Fix Item2 Lock button [present only if the associated vector has a second property that can be ‘looped over’]: If this is locked, the associated vector’s secondary property will not change when the calculation is applied to other items.

Note that the items selected as the things that can be looped over is calculated and updated dynamically as vectors are dropped onto the rows of the variables table. If the associated vectors have several different properties that can be looped over, the properties that occur most often are selected. Most commonly, though, for summary data the items will be well names. For grid data (Init or solution data) the items will be timesteps.

Apply to Multiple Cases or Items

When vectors have been associated with the variables, the ‘Apply to all…’ checkboxes above the variables table will be active. There are three ‘Apply to all’ options, but they may not all be visible or enabled. Which options are visible/enabled will depend on the properties of the associated vectors (whether the current project contains multiple cases and whether there are one or two item properties that can be ‘looped over’).

  • Apply to all cases [always visible; enabled if the current project contains multiple cases]: If this is checked, the calculation is performed for all cases in the current project. For each case, the associated vectors are replaced with the corresponding vectors from that case (unless they have been set to be fixed, or have fixed case, in the variables table).
  • Apply to all Items [only visible if (at least one of) the associated vectors has a variable property (such as wells or timesteps); that is, if the variables table has an ‘Item’ column]: If this is checked, the calculation is performed for all corresponding items (well, timesteps, etc.). For each item, the associated vectors are replaced with the corresponding vectors for that item (unless they have been set to be fixed, or have fixed item, in the variables table).
  • Apply to all Items2 [only visible if (at least one of) the associated vectors has a second variable property (completion index, for example); that is, if the variables table has an ‘Item2’ column]: If this is checked, the calculation is performed for all corresponding secondary item properties. For each secondary item, the associated vectors are replaced with the corresponding vectors for that secondary item (unless they have been set to be fixed, or have fixed secondary item, in the variables table).
Result Location

The Result Location box specifies the location in the Project View where the calculated vector should be placed. This can be set in two ways:

  • Automatically: When the associated vectors have been set for one or more of the variables, the properties of those vectors are analysed to determine whether the free vectors (that is, the vectors that have not been set to be fixed or have fixed case or other properties) all belong to a single case and/or item (well or timestep, etc.). If they are consistent, the result location is set to be the corresponding location (with that case and item properties) in the Project View. When the result location has been set automatically, the text is grey and italic.
  • By the user: To set the result location to a specific place in the Project View drag and drop a vector from the desired branch of the Project View onto the yellow Result Location box (the name of the vector dropped will be ignored, only the path will be used). When the result location has been set by the user the text is black.

Once the result location has been set the corresponding case is displayed. If the current project contains multiple cases, this is a dropdown that allows the case of the result vector location to be changed. Usually, this will not be necessary, and note that the result location is included in the analysis of whether the case is a free property that can be looped over, so if the result vector’s case is set to be different from the variable’s associated vector cases it will not be possible to apply the calculation to all cases.

Validation Messages and the Calculate Button

The section of the Calculation panel below the Variables section contains the validation message and the Calculate button:

  1. If there is any problem with the calculation setup (a syntax error in the formula, not all variables being associated with vectors, etc.) a validation indicator icon and message will be displayed and the Calculate button will be disabled. The validation icon indicates the severity of the error ( No Error, Information, Warning, Severe Error). If there are no errors or warnings, and ‘No errors’ will be displayed and Calculate will be enabled.
  1. Clicking Calculate will perform the requested calculation(s). Note that the new vectors will appear in the Project View, but the actual evaluation will not be performed until the vector is used on a line plot or grid plot, etc.

The Sum (SUM) and Average (AVG) Functions

S3analyse can perform calculations involving sums or averages over items such as Wells or timesteps. The list of items over which the sum or average should be performed can be specified by the user.

To set the list of items to sum or average over follow these steps:

  1. Enter a formula containing the SUM() or AVG() function, operating on a variable or expression (e.g., SUM(a), or SUM(a+b*c)).
  1. Associate the variables in the SUM or AVG function with vectors. At least one of the associated vectors must have properties that can be summed or averaged over. For example, well vectors or solution vectors can be summed or averaged over, but FIELD vectors or INIT vectors cannot (the expression can include Summary Field or Init vectors, but there must be at least one other vector in the SUM or AVG expression that can be summed or averaged over). The associated vectors are validated, and the validation status of the SUM or AVG function is indicated by the coloured line under the function name. The actual error will be indicated in the error reporting box at the bottom of the calculation panel (unless a different, more severe, error is reported there).
  1. When the function has been set up correctly, so that the function’s validation status indicator is green, hovering over the function will show the Select button (this only appears when the cursor is close to the function text). Clicking Select will show the Select Items dialog:

  1. In the Select Items dialog, items may be selected by specifying a pattern with wildcards (P*, for example), and/or by individually selecting/deselecting the items. Once the desired items have been selected, click Close on the Select Items dialog, and the sum or average function setup is complete.
